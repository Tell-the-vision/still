# 문서(PDF) → 웹뷰 변환 실험 결과 — 기본 파서 + Gemini

대상: `hirst-ebook.pdf`(Figma 내보내기, 29쪽 A5, 텍스트 위주) · `OS24-03-can-i-see-you.pdf`(실제 갤러리 작품 시트, InDesign, 6쪽, 사진 4면 + 3개국어 2면)
질문: ① 원본이 웹뷰에서 얼마나 보존되는가 ② CSS만으로 되는가, EBOOK 뷰어 모듈이 필요한가 ③ Gemini는 어디에 쓰는 게 맞는가
기준: 서비스는 **모바일**(390px 폭)이다.

## 1. 결론 먼저

- **텍스트 원문 보존은 파서가 책임지고, 모델은 손대지 않는 구조가 맞다.** 파서(텍스트 레이어)에서 뽑은 문장을 그대로 쓰면 보존율은 정의상 100%. Gemini에게 "원문 그대로" 제약을 걸고 돌려도 29쪽 중 3쪽·20개 섹션 전부에서 문장 커버리지 1.000이 나왔지만, 이건 매번 검증해야 하는 수치이고 파서는 검증이 필요 없다.
- **"원본 그대로의 페이지"는 CSS만으로 복원된다.** 줄 단위 좌표 + 웹폰트 + 괘선/이미지 좌표로 만든 HTML이 PDF 래스터와 픽셀 유사도 0.94(Figma) / 0.99(InDesign). 단, (a) 폰트 자간이 달라 줄이 넘치는 문제는 줄 폭 맞춤(`scaleX`)으로 해결해야 하고, (b) 모바일에서는 본문 6~10pt가 그대로 축소돼 읽을 수 없다.
- **그래서 모바일 기본 화면은 "복원"이 아니라 "리플로우"여야 하고, 뷰어 모듈은 "원본 PDF 보기" 보조용이다.** 리플로우는 원문·순서·위계·이미지-캡션 짝·타이포 시스템(서체·굵기·비율)을 보존하면 된다. pdf.js 같은 뷰어는 원본을 그대로 보고 싶을 때(디자인이 중요한 도록, 도면)만 띄우면 되고, 필수는 아니다.
- **실제 전시 PDF에서 파서가 깨진 곳은 두 군데: 다단(column) 읽기 순서와 리스트.** `parse_pdf.py`의 y 정렬은 3단 영문/국문 본문을 줄 단위로 섞어 버린다(원문 글자는 다 있지만 읽을 수 없는 순서). 블록의 왼쪽 가장자리로 단을 묶어 단→줄 순서로 읽는 `columns.py`로 고쳤다. 연도+내용 리스트는 아직 한 문단으로 합쳐지므로 리스트 감지가 필요하다.
- **Gemini가 실제로 값을 더한 곳은 "텍스트 레이어에 없는 것"이었다.** Figma PDF의 목차 번호 `1. 2. 3.`과 불릿 `•`은 글자가 아니라 도형이라 어떤 파서에도 없는데, 페이지 이미지를 같이 준 Gemini 레이아웃 패스는 이를 복원해 넣었다(그래서 "추가된 문장"으로 잡힘). 역할 분담: 파서 = 글자, 모델 = 이미지에만 있는 구조(번호·불릿·캡션-이미지 짝·읽기 순서 판정).

## 2. 숫자

### 2-1. 원본 복원(AI 없음) — 페이지 단위, PDF 래스터 대비

| 문서 | 방식 | 픽셀 유사도 | 잉크 IoU(4px) | 비고 |
| --- | --- | --- | --- | --- |
| Figma 29쪽 | 래스터+투명 텍스트레이어 (`view-raster.html`) | 1.000 | 1.000 | pdf.js 원리, 라이브러리 없음. 7.5MB |
| Figma 29쪽 | CSS 절대좌표 + Pretendard (`view-css.html`) | 0.939 | 0.36 (6pt 블록 기준 0.65) | 줄바꿈·괘선·푸터 동일, 글리프 굵기만 차이 |
| InDesign 6쪽 | 래스터+텍스트레이어 | 0.997 | 0.88 | |
| InDesign 6쪽 | CSS 절대좌표 + 세리프 대체폰트 + 줄폭 맞춤 | 0.987 | 0.84 | 줄폭 맞춤 전에는 2단 본문이 옆 단으로 넘침 |

### 2-2. Gemini (gemini-2.5-flash, AI Studio 엔드포인트) — Figma PDF

| 패스 | 단위 | 문자 유사도 | 문장 커버리지 | 토큰 | 시간 |
| --- | --- | --- | --- | --- | --- |
| A 구조화 (줄→역할 JSON) | 3쪽 | 0.996 | 1.000 | 2.5k in / 1.7k out | 9.5초/쪽 |
| B 리플로우 (segments→HTML) | 20섹션(전체) | 1.000 | 1.000 | 15.5k in / 14k out | 12.6초/섹션, 총 4.2분 |
| C 레이아웃 (페이지 이미지+줄→HTML/CSS) | 3쪽 | 0.954 | 1.000 | 3.3k in / 3.4k out | 15초/쪽 |

C의 0.954는 누락이 아니라 **추가**(목차 번호·불릿을 이미지에서 읽어 넣음). C의 시각 유사도는 0.93(잉크 IoU 0.34 — 글자 굵기·위치가 "비슷하게"까지만). 29쪽 전체면 호출 58회·약 8분·약 15만 토큰.

### 2-3. 파서 — 실제 전시 PDF

| | `parse_pdf.py` (y 정렬) | `columns.py` (단 인식) |
| --- | --- | --- |
| p5 영문 3단 | "About the Artist"와 "About the Work" 문단이 줄 단위로 교차 | 단별로 순서대로 |

## 3. EBOOK 뷰어/모듈이 필요한 경우

| 필요한 것 | 언제 | 선택지 |
| --- | --- | --- |
| 없음 (CSS/HTML만) | 텍스트 위주 문서의 리플로우, 또는 줄 좌표 기반 복원 | 지금 방식. 폰트는 Pretendard(산세리프)·Noto Serif KR(세리프) 2종이면 대부분 커버 |
| 임베디드 폰트 그대로 | 세리프 도록처럼 서체 자체가 디자인일 때 | PDF 안의 서브셋 폰트를 꺼내 `@font-face`로 (pdf.js가 자동으로 하는 일). 라이선스는 "그 문서 표시용"으로만 |
| PDF 뷰어 | "원본 보기" 버튼, 도면·포스터처럼 레이아웃이 내용인 페이지 | 웹뷰: pdf.js(~1MB, 텍스트 선택·검색됨) / RN: react-native-pdf(네이티브) / 가장 가벼움: 페이지 SVG 또는 PNG + 투명 텍스트레이어(본 실험의 `view-raster`) |
| EPUB 리더 | 입력이 EPUB일 때 | 리더 없이도 됨: EPUB은 zip+XHTML이라 `parse.mjs`처럼 직접 풀어 HTML로 바로 띄우는 게 더 단순. epub.js는 페이지네이션·북마크가 필요할 때 |
| OCR | 스캔 PDF(샘플 -1) | Gemini 비전으로 가능(텍스트 레이어가 없으니 이때는 모델이 글자를 만든다 → 사람이 검수) |
| Office 파서 | docx/pptx/xlsx(샘플 7~10) | python-docx / python-pptx / openpyxl 또는 LibreOffice → PDF 변환 후 같은 파이프라인 |

## 4. 제안하는 파이프라인

```
입력(PDF/EPUB/docx…) ──▶ 파서 ──▶ segments.json (원문 그대로, 단·문단·역할·좌표·이미지)
                                   │
                    ┌──────────────┼──────────────────┐
             모바일 리플로우      원본 보기(선택)        STILL 가이드
             (HTML+CSS, 타이포     (래스터+텍스트레이어   (sections → sentences,
              시스템만 적용)        또는 pdf.js)          스크랩 단위)
                                   
Gemini는 segments.json을 "보정"하는 한 번의 호출: 페이지 이미지 + segments → {읽기 순서 수정, 리스트/번호/불릿 복원,
이미지-캡션 짝, 제목 위계 확정}. 글자는 바꾸지 못하게 id로만 참조(일영님 설계대로).
```

## 5. 남은 일

- `columns.py`의 리스트 감지(연도/탭/불릿으로 시작하는 줄은 `<li>`)와 제목이 본문 밴드에 들어가는 문제(p6 "작가에 대하여")
- Gemini "보정 패스"를 실제로 구현해 A/C 대신 쓰기 (지금 A는 구조만, C는 HTML까지 만들어서 너무 많이 함)
- 임베디드 폰트 추출 → `@font-face` 시도 (세리프 도록 대응)
- 엣지 케이스(-1 스캔, -3 2단, -7/8 docx, -16 zip)는 위 구조가 정해진 뒤에
